# ADR-0022 — تضمین کیفیت جامع: کاتالوگ ۱۰نوع تست + حافظهٔ باگ + Runner تولیدپذیر

- وضعیت: **Accepted**
- تاریخ: فاز ۱۸ (PHASE 18 — Complete Quality Assurance)
- دامنهٔ تصمیمهای مهندسی: ED-197..206
- مرتبط: ADR-0019 (Observability) · ADR-0020 (Performance) · ADR-0021 (Reliability)

## Context

فرمان فاز ۱۸: ممیزی تستهای موجود، ایجاد/تکمیل ۱۰ نوع تست برای Critical Path، «کیفیت پوشش > عدد پوشش»، برای هر باگ یک Regression Test، و هدف Critical Bug = ۰. قبل از این ADR پروژه ۵۹۳ تست سبز داشت اما: نوع‌بندی اعلام‌نشده، نقشهٔ Critical Path صریح نداشت، حافظهٔ باگ (regression) نداشت، و تولیدپذیری suite در اجراهای تکراری شکسته بود (stock مصرف‌شده، پورت مسموم).

## Options

1. **افزایش عدد پوشش**: ابزار line-coverage + هدف ۸۰/۹۰٪ — عدد زیبا، سیگنال کم؛ خطوط UI پر میشوند در حالی که مسیر پول میتواند بدون تست بماند.
2. **سوئیتهای ad-hoc بهازای هر باگ تاریخی**: پراکنده، بدون catalog، بدون الزام CI — باگ بعدی دوباره قفل نمیشود.
3. **(انتخاب) کاتالوگ نوع‌بندی‌شده + حافظهٔ باگ + Runner واحد + گیت CI**: نوع‌ها کد واقعی را نوع‌بندی میکنند؛ ۴ مسیر بحرانی صریحاً map میشوند؛ هر باگ REG-* قفل تست دارد؛ یک فرمان (`qa-run.sh`) کل چرخه را تولیدپذیر میکند؛ گیت QA1..QA10 همه را enforce میکند.

## Decision

1. **کاتالوگ ED-197**: ۱۰ نوع (Unit/Integration/API/Database/Security/E2E/Regression/Performance/Load/Contract) به‌صورت سوئیت واقعی روی دیسک؛ «نوع» یعنی فایل/سوئیت با سربرگ provenance، نه برچسب.
2. **نقشهٔ ED-198**: پذیرش پوشش = سبز بودن ۴ مسیر بحرانی (سفر طلایی/مسیر پول/ماتریس RBAC/inventory مسیر) — نه عدد درصدی.
3. **حافظهٔ ED-199**: هر باگ شکارشده در طول عمر پروژه = یک قفل REG-* در `tests/regression` — رفع باگ بدون قفل، فقط تعویق باگ است.
4. **Runner ED-200/201**: `qa-run.sh` با جداسازی NODE_ENV، پنجرهٔ settle، teardown، و **گارد مالکیت پورت** — suite هرگز علیه سرور جاعل (dev رهاشده روی :3000) اجرا نمیشود؛ این عیب واقعاً ۹ شکست کاذب ساخته بود.
5. **Inventory ED-202/203**: مرجع مسیرهای واقعی (actual) مرجع تطبیق است؛ مصرف stock در اجراهای تکراری مشروع است پس تست باید کل کاتالوگ را اسکن کند (تولیدپذیری داده).
6. **بهداشت ED-204/205/206**: سربرگ provenance الزامی؛ ممنوعیت skip/only/TODO با word-boundary (ورودیهای adversarial عمدی مثل HACKED_FIELD مجازند)؛ کلاینت تست مشترک با کش session (rate-limit ایمن بین suiteها).

## Consequences

- ✅ Critical Bug = ۰ و قابل اثبات: هر باگ شناخته‌شده قفل تست دارد و inventory مسیر کلاس مفقودی فایل را میبندد.
- ✅ علت ریشه‌ای REG-02 شکار و بسته شد: الگوی bare `test` در .gitignore پوشهٔ مسیر source با نام test را خاموش میبلعید — قفل hygiene گیت QA3 (الگوهای غیرمهارشده ممنوع) + رفع الگو.
- ✅ تولیدپذیری: دو اجرای کامل پشت‌سرهم سبز (۵۹۳/۵۹۳).
- ✅ سیگنال صادق: gate روی «کیفیت» (نقشهٔ مسیر + hygiene + قراردادها) قفل است، نه عدد.
- ⚠️ پوشش خط-به-خط گزارش نمیشود (D-18-1) — بدهی صریح؛ جایگزین فعلی نقشهٔ مسیر صریح است.
- ⚠️ فلکِ async-export زیر بار suite کامل یکبار دیده شد (D-18-5) — واتچ میشود.

## Compliance

- گیت CI: `npm run audit:qa` → QA1..QA10 (scripts/qa-audit.mjs) — از جمله inventory مسیر و commitشدن رفعهای بحرانی.
- اجرا: `bash scripts/qa-run.sh` → ۵۹۳/۵۹۳ روی سرور production standalone با BH_CHAOS=1.
- Regression: `tests/regression/regression.test.ts` (REG-01..REG-07) + `scripts/smoke-phase18.sh` (قفل HTTP-level).
- مستند: `docs/QA.md` (۱۲ بخش؛ کاتالوگ ED-197..206 و بدهیهای D-18-*).
