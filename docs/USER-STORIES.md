## استوری‌های Edge Case و Resilience (ترنس‌ورس)

این استوری‌ها از سناریوهای §56 Master Prompt استخراج شده‌اند و رفتار سیستم در شرایط غیرعادی را تعیین می‌کنند. جزئیات جریان در `USE-CASES.md §6`.

> **نگاشت یک‌به‌یک:** `US-EC-NN ↔ AC-EC-NN` (شماره یکسان؛ مثلاً US-EC-01 ↔ AC-EC-01) — معیار پذیرش هر استوری در جدول «AC — Edge Cases» سند ACCEPTANCE-CRITERIA.md آمده است.

| ID | استوری | پاسخ مورد انتظار |
|---|---|---|
| US-EC-01 | اگر کاربر هم‌زمان چند بار «پرداخت/تأیید/ثبت» را کلیک کند | فقط یک عملیات مؤثر؛ بقیه Idempotent رد |
| US-EC-02 | اگر دو کارشناس هم‌زمان یک پرونده را Claim کنند | فقط یک Claim موفق (Lock اتمیک)؛ دیگری پیام «قبلاً گرفته شد» |
| US-EC-03 | اگر Callback پرداخت دوبار برسد | بدون تغییر دوم؛ Log رکورد تکرار |
| US-EC-04 | اگر پرداخت هم‌زمان با لغو سفارش انجام شود | ترتیب با Transaction/Lock تعیین؛ یک مسیر نهایی |
| US-EC-05 | اگر قیمت محصول هنگام پرداخت تغییر کرده باشد | قیمت لحظه تأیید ملاک + شفافیت تاریخچه؛ تسویه بر اساس Invoice |
| US-EC-06 | اگر نسخه هم‌زمان توسط دو نقش ویرایش شود | Version جدید از هر تغییر + Immutability نسخه‌های قبلی |
| US-EC-07 | اگر AI خطا/Timeout دهد | ثبت خطا، Retry، ادامه مسیر انسانی؛ پرونده متوقف نمی‌شود |
| US-EC-08 | اگر SMS Provider قطع باشد | اعلان In-app می‌رود؛ SMS با Retry/Backoff در SMSLog |
| US-EC-09 | اگر ذخیره‌سازی تصویر fail شود | rollback امن، پیام خطای قابل‌فهم، عدم ثبت نیمه‌کاره |
| US-EC-10 | اگر تصویر quality-reject شود | پیام علت + راهنما + امکان آپلود مجدد نامحدود منطقی (Rate-Limited) |
| US-EC-11 | اگر کاربر پرداخت را رها کند (Proforma تأیید شده ولی پرداخت نه) | SLA انتظار (ED-08)؛ Reminder؛ Auto-cancel با مسیر بازگشتی |
| US-EC-12 | اگر بیمار تأیید ادامه درمان را ندهد | SLA + Reminder؛ Auto-close با دلیل + امکان شروع مجدد |
| US-EC-13 | اگر اقلام نسخه ناقص باشند | Proforma فقط اقلام موجود + ارجاع جایگزین (ED-06) |
| US-EC-14 | اگر آپلود فایل مخرب/کال寇 (Malformed) انجام شود | رد پیش از ذخیره؛ Log امنیتی؛ نام Random |
| US-EC-15 | اگر توکن نشست منقضی وسط عملیات شود | Auto-Refresh بدون از دست رفتن کار کاربر |
| US-EC-16 | اگر رکورد درخواستی وجود نداشته/حذف نرم شده باشد | 404 با فرمت خطای استاندارد؛ بدون افشای وجود/عدم وجود حساس |

> این استوری‌ها در ACCEPTANCE-CRITERIA معادل‌های AC-EC دارند و در RTM با تست‌های Integration/Chaos نگاشت شده‌اند.
